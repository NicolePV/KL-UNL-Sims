# Conversion Notes — Photometry Simulator (Flash/AS3 → Accessible HTML5)

## Behavior model

The sim teaches aperture photometry. A deterministic 400×300 16-bit "CCD
image" is built from Gaussian read noise (mean 2318, σ 426, generated by a
seeded Lehmer LCG + polar Box–Muller, then chunk-shuffled with the same LCG)
plus 25 stars, each stamped as an Airy-disc PSF (radius 4, Bessel-J1) with
flux `peakValue · 10^((3 − magnitude)/2.5)`; displayed through a γ=1.8
grayscale transfer function. Two draggable apertures (inner disc r=5 inside
an outer sky ring r=10) can be moved over the field; for each, the sim shows
a 23×23-pixel zoom window with the aperture outlines, per-region statistics
(numPixels / counts / average for the inner disc and the ring = outer minus
inner), and the sky-subtracted flux `f = counts_disc − numPixels_disc ×
average_ring`. The magnitude difference `m1 − m2 = −2.5·log10(f1/f2)` is
shown ("…" when the ratio is not positive). Hovering/arrow-keying inside a
zoom window inspects individual pixels (x, y, counts); selecting a pixel in
one window clears the other. A checkbox toggles the "1"/"2" aperture labels.
Nothing animates; the field never changes after construction (epoch and
noiseSeed are never touched by the main timeline).

## Source → HTML5 mapping

|---|---|

| `StarField.as` (generateNoise / shuffleNoise / update / getStatistics / getPixelInfo / getPixelColors) | `field` closure in `simulation.js`; identical LCG (x→x·16807 mod 2³¹−1), Box–Muller pairs, chunk table (280 chunks × 430), star-flux add through the chunk indirection; computed once since the field is static |

| `GammaTransferFunction.as` (γ=1.8, not inverted) | `greyTable` lookup (int-cast `255·(v/peak)^(1/γ)`) |

| Flash FocusManager / CheckBox component | native `<input type="checkbox">` + label ("label the apertures", verbatim from AS) |
| stage offsets: starField at (14,62); apertures at stage (210,250)/(100,100) | all logic runs in field coordinates; initial centers (196,188)/(86,38) — identical |

81 / 183884 / 2270.17; ring 236 / 543626 / 2303.50; f2 = −2699.50;

## Assets reused vs code-drawn

- **Reused as-is:** `assets/shapes/50.svg` — the exported pixel-info speech
  balloon, used as the tooltip background at its original 111×70.5 px size,
  tail tip anchored at the active pixel (as `pixelInfoMC` did).
- **Not applicable:** the decompiled export contains **no bitmaps**
  (`images/` is empty). The remaining `shapes/*.svg` are Flash UI-component
  chrome (CheckBox skins, focusRect, and shape 59 = the equation fraction
  bar): per the hard rules these are replaced by native controls, KL-UNL
  chrome, and MathJax respectively, not ported.
- **Code-drawn (recreated on canvas):** the star-field bitmap, aperture
  outlines, zoom-window checkerboard/cells/markings, active-pixel outline —
  all generated at runtime by ActionScript in the original.
- Fonts: the exported `fonts/*_Verdana.ttf` subsets are not shipped; the
  aperture labels use the system `Verdana, Geneva, … sans-serif` stack in
  HTML (zoomable), colored with the aperture outline colors.

## contents.json

The `photometrySimulator` entry **already existed** in the shared
foundation `contents.json`, so no new entry was added. In the per-sim copy at
`foundation/contents.json`:

1. Per instruction, the About sentence "Permission is granted to use these
   files for noncommercial purposes as long as they remain unmodified." was
   replaced with the Apache License 2.0 notice (Copyright 2026 The Board of
   Regents of the University of Nebraska). The rest of the About/Help text
   is untouched. (This entry has no NSF funding line to preserve.)
2. **JSON-validity repairs (necessary for the masthead to load at all):** the
   source file is not valid JSON — browsers' strict `JSON.parse` rejects it,
   so `fetch(...).json()` fails and the masthead renders empty. Fixed in the
   copy only (same fixes already present in sibling converted sims):
   - unescaped quotes in two `href="..."` attributes (`renaissancePtolemaic`
     and `venusphases` entries);
   - four raw newlines inside string literals (`ce_hc`, `eclipsingbinarysim`
     entries) joined;
   - one literal TAB inside a string (position ≈88751) replaced with a space.
   No wording was changed by these repairs. If the pipeline treats
   contents.json as one shared file, apply the same repairs upstream.

The foundation `.js`/`.css` files are byte-for-byte unchanged. MathJax is
self-hosted at `foundation/mathjax/tex-mml-chtml.js` (same layout as the
other converted sims in this collection) because rule 5 forbids CDNs; the
linked folder's `foundation/` did not include it and no demo HTML was
present, so the copy was taken from the sibling "Radial Velocity Simulator"
conversion.

## Deviations from the original (all presentation-level, per Goals B/C)

- **Layout** follows the provided target capture inside the KL-UNL shell
  (Star Field + Magnitude Difference Calculation at left; Aperture 1/2 Info
  panels at right, each zoom window beside its stats) instead of the Flash
  pixel layout. Reading/tab order is DOM order (apertures → checkbox → zoom
  windows) rather than the Flash tabIndex order (zooms first).
- The equations (f1, f2, m1−m2 with values) are typeset by MathJax; the
  original drew them as static text fields with a hand-drawn fraction bar.
  The en-dash minus in the Flash text renders as a proper math minus.
- The masthead (title/Reset/Help/About) is the shared KL-UNL component; the
  original had no Reset/Help/About buttons on stage.
- Zoom-window pixel inspection: the original focused the window on mouse
  roll-over; on the web, hover updates the inspected pixel without stealing
  keyboard focus, click/tap focuses, and keyboard focus still selects the
  center pixel first (as `onFocusIn` did). Leaving the window (or blurring)
  clears the selection, matching the original.
- Keyboard additions (accessibility, not behavior changes): Shift+Arrow /
  PageUp/PageDown larger steps for apertures; PageUp/PageDown/Home/End in
  the zoom windows. Arrow keys keep the original 1-pixel step.
- Aperture drag proxies have an enlarged (~44 px) invisible hit area for
  touch; the drag/snap math is unchanged (canvas-relative coordinates).
- On narrow screens the wide f1/f2 equations scroll inside their own
  container (WCAG reflow) rather than overflowing the page.

## Cross-browser notes

Standards-only APIs: Pointer Events, canvas 2D, CSS grid/flex, custom
element (masthead), `aspect-ratio` with `height:auto` fallback behavior.
`String.prototype.padStart` (Safari 10+). No vendor-prefixed CSS. Canvas
uses a fixed internal coordinate system (400×300 / 184×184 at 2× backing)
scaled by CSS; pointer coordinates are mapped through the live bounding rect,
so drag/snap math is identical at any display size, including iOS Safari
(touch-action:none on draggables).
